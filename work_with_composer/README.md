# Пояснительная записка

## doctrine/orm ^3.7 — слой доступа к данным (пункт 1 ТЗ)

``Зачем`` Обеспечивает объектно-реляционное отображение: сущности PHP ↔ таблицы БД. Позволяет описывать модель данных декларативно (атрибуты/аннотации), строить запросы через DQL или QueryBuilder, управлять транзакциями и жизненным циклом объектов.

``Связи`` Doctrine — центральный потребитель кеша (symfony/cache) и источник данных для формирования отчётов, PDF, выгрузок. Транспортно-независим: не привязан к Symfony, но бесшовно с ним интегрируется.

## symfony/cache ^8.1 — кеш в памяти (пункт 2 ТЗ)

``Зачем``. Реализует PSR-6 и PSR-16 интерфейсы кеширования с адаптерами под Redis, Memcached, APCu, файловую систему. Позволяет кешировать результаты тяжёлых запросов к БД, а также метаданные Doctrine.

``Связи``

    С doctrine/orm — кеширование метаданных и запросов (второй уровень кеша).

    С aws/aws-sdk-php — при горизонтальном масштабировании Redis-адаптер может быть вынесен на отдельный узел, но это уже инфраструктура.

    Требует расширения ext-redis или predis/predis как драйвера. В текущем composer.json драйвер не подключён явно — предполагается, что в системе стоит ext-redis (нативный, быстрее) либо драйвер будет добавлен позже.

## symfony/mailer ^8.1 + symfony/mime ^8.1 — отправка e-mail (пункт 6 ТЗ)

``Зачем`` symfony/mailer — транспорт для отправки писем (SMTP, sendmail, API-транспорты Mailgun/Postmark/SES/Sendgrid). symfony/mime — построение MIME-сообщений: заголовки, вложения, multipart, кодирование.

``Связи``

    С doctrine/orm — источник данных для писем (пользователь, заказ, товары).

    С PDF/XLS-генераторами — вложения. В текущем composer.json генераторы отчётов не подключены — это пробел, который нужно закрыть (см. раздел 4).

    С symfony/serializer — не связан напрямую, но оба пакета — часть экосистемы Symfony.

    С guzzlehttp/guzzle — API-транспорты Mailer внутри используют HTTP-клиент. Guzzle для этого не обязателен (Mailer использует symfony/http-client), но наличие Guzzle покрывает другие нужды.

## guzzlehttp/guzzle ^8.2 — HTTP-клиент (интеграции, пункты 8, 10, 11 ТЗ)

``Зачем`` Универсальный HTTP-клиент для обращения к внешним API: службы доставки (PickPoint, Почта России, СДЭК), Яндекс.Маркет, платёжные шлюзы.

``Связи``

    С aws/aws-sdk-php — AWS SDK внутри использует Guzzle как HTTP-обработчик. Это не дублирование, а совместимость: вы можете передать свой сконфигурированный Guzzle-клиент в AWS SDK.

    С платежами/доставкой/Маркетом — SDK этих сервисов либо не существуют на Packagist, либо внутри используют Guzzle, либо подключаются как обёртки над Guzzle.

    С symfony/mailer — часть API-транспортов может использовать Guzzle, но по умолчанию Mailer предпочитает symfony/http-client. Наличие обоих не конфликтует.

## aws/aws-sdk-php ^3.401 — облачное хранилище (пункт 7 ТЗ)

``Зачем`` Официальный SDK для AWS. В контексте задачи — работа с S3 для хранения статичных файлов: изображения товаров, документы, выгрузки, бэкапы.

``Связи``

    С guzzlehttp/guzzle — AWS SDK использует его как HTTP-транспорт (см. 2.4).

    С symfony/cache — опционально: кеширование метаданных S3 (списки объектов, ETag). На практике редко нужно.

    С doctrine/orm — в БД хранятся только ключи/URL объектов, сами файлы — в S3. Это разделение ответственности: БД для структурированных данных, S3 для бинарных.

## league/oauth2-google ^5.0 — авторизация через соцсети (пункт 9 ТЗ)

``Зачем`` OAuth 2.0-провайдер для входа через Google. Расширяет базовый league/oauth2-client.

``Связи``

    С doctrine/orm — хранение связи user_id ↔ provider_user_id.

    С guzzlehttp/guzzle — oauth2-client использует Guzzle для HTTP-запросов к Google. Это прямая зависимость: league/oauth2-client требует guzzlehttp/guzzle в своём composer.json.

    С symfony/mailer — после успешной регистрации через Google обычно отправляется welcome-письмо.

## symfony/serializer ^8.1 — сериализация данных (пункты 10, 11 ТЗ)

``Зачем`` Преобразование объектов PHP ↔ JSON/XML/CSV. Нужен для:

    формирования XML/JSON-фидов для Яндекс.Маркета (пункт 10),

    обработки ответов платёжных шлюзов и API доставки (пункты 8, 11),

    REST API проекта (если есть).

``Связи``

    С doctrine/orm — сериализация сущностей и коллекций (осторожно с ленивой загрузкой и циклами — нужны группы).

    С guzzlehttp/guzzle — ответы API десериализуются в DTO через Serializer.

    С symfony/mime — не связан напрямую, оба — часть Symfony-экосистемы.

## phpunit/phpunit ^13.4 — тестирование (пункт 12 ТЗ, dev-зависимость)

``Зачем`` Фреймворк модульного тестирования. Вынесен в require-dev, потому что в продакшене не нужен.

``Связи``

    Со всеми продакшен-пакетами: тестируется их использование в коде проекта.

    С doctrine/orm — тестовая БД в памяти, фикстуры, откат транзакций.
